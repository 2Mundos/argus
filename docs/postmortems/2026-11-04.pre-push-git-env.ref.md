# Postmortem: The pre-push checks rewrote the repository they guard

Date: 2026-11-04
Incident / PR: the pre-push hook fix (branch `fix/pre-push-git-env`)

## Summary

A push from a worktree ran `make check-changed` inside the pre-push hook, and the
NanoClaw commit attribution tests then committed to, renamed branches in, and
reconfigured the developer's real repository. Git exports `GIT_DIR` (and in a
worktree `GIT_INDEX_FILE` and more) to hooks; the hook passed them on to every
check, and a test's `git init` or `git commit` in a temporary directory followed
them to the real repository. One test already guarded itself against this; the
hook did not guard the rest. Lesson: a hook must give the commands it runs the
environment they would have outside it.

## Impact

One developer checkout, about four seconds of test run, found minutes later. The
shared repository config got `core.bare = true`, `core.hooksPath` pointing into the
worktree, a `[user]` identity and an `alias.ci`; local `main` was overwritten by the
pushed branch renamed with `branch -M main`, plus three test commits; the worktree's
index got test files. The push itself failed, and nothing reached GitHub (its
`main` was checked by parent commit). Everything was restored from the reflog and a
copy of the config.

## Mechanism

`git push` runs `.githooks/pre-push` with `GIT_DIR`, `GIT_INDEX_FILE` and, for a
linked worktree, more location variables set. Git honours them over the current
directory. `integrations/nanoclaw/tests/test_commit_attribution.py` runs the real
`git` with `cwd=<tmp dir>` and `os.environ`: `init`, `config user.*`, `commit`,
`branch -M main`, `config core.hooksPath`, `push -u origin main`. With the hook's
variables, each one acted on the repository being pushed. `git init` with `GIT_DIR`
and no work tree set `core.bare = true`. The `push` failed only because the
repository's own pre-push hook rejected it; otherwise `origin` was the real remote
and the test commits sat on top of `origin/main`.

## Why it escaped

- CI runs the same tests outside a hook, so they pass there and touch only their
  own temp directories.
- `scripts/test_release.py` scrubs `GIT_*` in its own fixture, with a comment
  naming this exact hazard; the fix stayed local to that test.
- The hook runs only the checks the changed files affect, so a push that never
  touched `integrations/nanoclaw` never ran these tests under it.

## Guardrails added

- Tests: `scripts/test_pre_push.py` runs the hook with a stand-in `make` and asserts
  the checks see no `GIT_*` location variable.
- Rules / checks: `.githooks/pre-push` unsets `git rev-parse --local-env-vars`
  before it runs anything.
- Specs: none; the hook is described in `AGENTS.md` and its own header.

## Lessons

1. A hook's environment is not the developer's: scrub it once, where the hook
   starts other programs, not in each program.
2. A test that runs real `git` must pin its repository by environment, not only by
   working directory.
3. A guard found in one test is a sign the same hazard exists elsewhere.
