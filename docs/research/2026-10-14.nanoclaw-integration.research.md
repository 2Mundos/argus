## Q1. Can a module inject inbound messages without a chat platform? — Yes

- Channel adapters self-register (`registerChannelAdapter`, `src/channels/channel-registry.ts`)
  and push messages with `setup.onInbound(platformId, threadId, message)`
  (`src/channels/adapter.ts`). Replies come back through the adapter's `deliver()`.
- The built-in `cli` channel (`src/channels/cli.ts`) is exactly this pattern: zero
  credentials, no platform, routed like any chat. An `argus` channel can copy it:
  `onInbound` per claimed task, `deliver()` mapped to progress/complete.
- Agent groups, messaging groups, and wirings are created with internal DB helpers
  (`createAgentGroup`, `createMessagingGroup`, `createMessagingGroupAgent`), as
  `scripts/init-cli-agent.ts` does; an Argus module can do the same at `onHostStart`
  (`src/host-lifecycle.ts`).
- **Install model is source-level**: skills copy files into `src/` and append an
  import to a barrel (`src/channels/index.ts`, `src/modules/index.ts`). There is no
  runtime plugin loader, so Argus ships an image built `FROM` NanoClaw with its
  channel file added and one import appended (or an `/add-argus` skill).

## Q2. Can the credential be switched per session? — Per agent group, fragile

- Credentials are a gateway seam (`docs/gateway-seam.md`): `sessions.ensure(input)`
  returns a typed contribution (env, mounts, containers, labels, network intent).
  Credentials never go into the agent container.
- OneCLI (`/add-onecli`) keys identity on the **agent group** (`ensureAgent({identifier:
  agentGroupId})`) and grants secrets with `onecli agents set-secrets`. Since one
  Argus agent = one agent group, switching an account = reassigning that group's
  secret. The skill pins OneCLI **1.42.0**: 1.43+ removed the assignment API.
- Not verified: whether a reassignment reaches an already-running session (decided
  inside OneCLI). Needs a live test.
- Iron Proxy uses principals/grants but needs PostgreSQL + a Rails console.
- Option to evaluate: an Argus gateway provider (credential-injecting proxy fed by
  Argus leases). Most control, most work.

## Q3. Does a host run on Kubernetes with DinD? — Open

- Only a Docker driver ships (`src/drivers/docker-driver.ts`, `NANOCLAW_RUNTIME_DRIVER`);
  the driver seam (`src/drivers/types.ts`) would allow a Kubernetes driver.
- Mounts are `hostPath` bind mounts. If the NanoClaw host itself runs in a container
  that talks to the Docker socket, those paths are resolved on the Docker host, not
  in the host container: its data directory must exist at the same path on both
  (or DinD with a shared volume). Unverified how the driver invokes Docker.
