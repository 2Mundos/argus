# Quota resume spike: a new NanoClaw session resumes a Claude Code session by id — Research

The evidence behind [quota resume](../specs/quota-resume.spec.md) 3.4 and 4.1. It
answers the open question of the [earlier research](2026-10-29.quota-resume.research.md):
how a NanoClaw session can start from a native session id. Run on 2026-11-02 in a temp
directory against a local fake Messages API. No credentials, no provider account and no
live NanoClaw install were used.

## Versions

| Component | Version |
| --- | --- |
| NanoClaw (read-only reference checkout) | `8fbacc91b6e2671d53c17fd0c866c0e2eef21715` |
| Claude Code CLI | 2.1.296 |
| Runner's `@anthropic-ai/claude-agent-sdk` | 0.3.296 |
| bun / node | 1.4.0 / v22.23.4 |

## Mechanism (from reading the pin)

- The agent runner keeps the Claude session it resumes in its own `outbound.db`,
  table `session_state(key, value, updated_at)`, key `continuation:claude`
  (`container/agent-runner/src/db/session-state.ts`). It adopts the legacy key
  `sdk_session_id` only when the current one is absent.
- At poll-loop start the runner reads that key, may rotate it (transcript over
  12 MiB or older than 14 days), logs `Resuming agent session <id>`, and passes it
  as `resume` to the SDK (`poll-loop.ts`, `providers/claude.ts`). On a query error
  matching `STALE_SESSION_RE` it clears the key, and the errored batch is acked
  completed (no redelivery).
- `.claude-shared` is per agent group and mounted as `/home/node/.claude` in every
  session container of the group. The cwd is always `/workspace/agent`. So every
  session of a group sees the same `projects/-workspace-agent/<id>.jsonl` files.
- The host creates the session row and `outbound.db` in `resolveSession`, before any
  container starts, and never writes `session_state` itself.

So a new session resumes an old conversation if its `outbound.db` holds the old id
under `continuation:claude` before its container first polls.

## Method

`integrations/nanoclaw/scripts/quota-resume-spike.sh` does the following:

- **Fake API.** It starts `fake-anthropic.mjs`, a streaming fake Messages API that
  logs every request body to a temp file.
- **CLI.** It runs the real `claude` CLI in `env -i` with only `PATH`, `HOME`,
  `TMPDIR`, the telemetry-off flags, `ANTHROPIC_BASE_URL` and
  `ANTHROPIC_API_KEY=gateway-managed`.
- **Runner.** It copies the pinned `container/agent-runner` to the temp dir, points its
  two mailbox paths at per-session files (two `sed` lines, checked), and drives
  one turn per session with `quota-resume-spike-runner.ts`. That driver uses the
  runner's own poll loop and Claude provider, and stops once the inbound message
  is acked.
- **Sessions.** All sessions share one `CLAUDE_CONFIG_DIR` and one cwd, as one group's
  sessions do. Sessions get their mailbox schema from the pinned host `schema.ts`.
- **Seed.** The seed is the shipped `seedClaudeContinuation`, imported from a
  NanoClaw checkout where `provision.sh check` installed the channel.

A random marker goes into the first turn. The script prints only ids, booleans and
counts: whether a request body contains the marker, never transcript text or the
environment.

## Command

```bash
env -u HTTPS_PROXY -u HTTP_PROXY -u https_proxy -u http_proxy -u NODE_USE_ENV_PROXY \
  NANOCLAW_REF=/tmp/nc/nanoclaw NANOCLAW_SRC=/tmp/nc/state/src \
  integrations/nanoclaw/scripts/quota-resume-spike.sh
```

The proxy variables are removed because the agent container's proxy does not pass
`127.0.0.1`. The script takes about 4 s.

## Findings

- **CLI.** `--resume <id>` keeps the id and resends the earlier turns. A fresh run
  does not. An unknown id fails before any request, with text the runner's
  `STALE_SESSION_RE` matches.
- **Runner, B.** A new session seeded with A's id resumed A's conversation.
- **Runner, C.** An unseeded session started fresh.
- **Seed.** It is idempotent for the same id, refuses a different one, and still
  accepts the same id after the run (the runner keeps it).
- **Runner, D.** A seed whose transcript is missing is cleared, and **that turn's
  message is acked without any model request**. In production that message is the
  task. The shipped channel therefore refuses to seed (and never reports `resumed`)
  unless the transcript still passes the runner's resume checks; the residual race
  is only a delete between that check and the first poll (spec 4.3).

## Limits

- The API was a fake with a placeholder key. Nothing here shows that Anthropic accepts a
  resumed conversation under another account (spec level 3).
- The runner ran outside a container, as a bun process with patched mailbox paths. It
  did not run inside the agent image, under the host's `resolveSession` and spawn.
- The memory hook was a no-op command. MCP servers were empty.
