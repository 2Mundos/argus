# Harness stderr tail — Research

Read-only investigation for [the draft](../drafts/2026-10-29.harness-stderr-tail.draft.md).
No code, spec, or other doc changes. Line numbers refer to
`integrations/nanoclaw/argus.ts` unless noted, checked against this checkout.

## 1. Question and answer

Can the harness's stderr be separated from model output today? **No.** The
NanoClaw runtime hook reads only container stdout via `docker logs`, so anything
written to stderr inside the container is dropped before Argus sees it. What
Argus keeps today is a 2 KiB, redacted tail of that stdout, and only on some
exit paths.

## 3. Disposable run

A fake docker CLI wrote `agent: ...` lines to stdout and
`claude: Error: 429 rate_limit` to stderr. The same
`execFile` + `stdout.trim()` pattern returned only the two stdout lines; the 429
line was lost.

Caveat: no real docker daemon was available. The fake CLI models the documented
`docker logs` routing (container stdout to CLI stdout, container stderr to CLI
stderr). It shows the wrapper's behaviour, not NanoClaw's.

## 4. Per exit class

"Captured today" means combined `docker logs` stdout only, 2 KiB, redacted.

| Exit class | Captured today? | Stored where | Visible to |
| --- | --- | --- | --- |
| Completion | No | Nowhere | Nobody |
| Failure, generic notice | Read, but only used to classify or add 3 lines / 300 chars | `reason` text on the failure (cap 1000) | Anyone who can read the task |
| Failure, classified | No (tail read only for generic notices) | Classification reason only | Anyone who can read the task |
| `session_lost` | Yes, up to 2 KiB | Inside `error` (cap 2000 chars), not an artifact | Anyone who can read the task |
| Startup failure | No | Host log line only (`safeText(msg)`) | Operator with host log access |
| `worker_env` block | No | `error` (1500 chars), fixed or `d.text` | Anyone who can read the task |
| Reply-delivery failure | No | `error` (2000 chars), fixed message | Anyone who can read the task |

In every row the stderr stream is absent.

## 5. Recommendation

Take the draft's second option: the improvement is the artifact and its flags;
separation is not needed for the goal.

1. **Capture stderr too.** Docker can give either separate streams or a merged
   one. Smallest change: have the host helper read both streams for
   `docker logs` (for example `execFile` result `{ stdout, stderr }`, or
   `docker logs` run so the CLI's stderr is concatenated). Both separation and
   combined capture are possible; combined is enough here. The redaction at
   L155 applies to the merged text.
2. **Attach a bounded attempt-level artifact `stderr-tail`.** Name is
   `stderr-tail`; the role must come from the existing `ArtifactRole` values
   (`apps/api/src/argus_api/artifacts/service.py:28`: `report`, `delegate_report`,
   `policy_snapshot`, `qa_receipt`, `other`). None fits well; `other` works
   without an enum change, a new role is a spec decision. Fields: `truncated`
   (bool), `complete` (bool), `bytes`, `redaction_version`.
3. **Pointer in the error string.** `session_lost` keeps a short pointer
   (artifact name and byte count) instead of the inline tail.
4. **Reads** follow [worker read scope](../specs/worker-read-scope.spec.md):
   the task's holder and managers.

## 6. Spec-update plan (before implementation)

Spec file names checked in `docs/specs/`; `task-delivery.spec.md` exists but is
about reference extraction and delivery state, so it is not the right home.

1. `worker-read-scope.spec.md`: state that `stderr-tail` follows the same read
   rule (task holder and managers), and that it never reaches events, the live
   feed, or metric labels.
2. `worker-lifecycle.spec.md` 3.12: replace "Container logs ... Not stored" with
   the bounded tail artifact (and 3.8 for the NanoClaw hook). Alternatively a
   short section in `task-live-log.spec.md` if the tail is framed as log data.
3. Artifact kind: choose `other` or add a role (see 5.2) and write the choice in
   the spec.
4. Caps: 16 KiB in-memory cap for the tail versus today's 2 KiB; decide whether
   the 2 KiB inline text remains for the error string. Define bytes versus code
   units explicitly (today's slice is code units).
5. Migration: none expected for a name-only artifact on `other`; a new role may
   need a schema check, not verified here. If so, next file is `0054_*.sql`.
6. Link the research and any spec change from `docs/README.md` (done for this
   research doc; spec changes are still to do).
