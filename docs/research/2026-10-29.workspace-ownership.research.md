## What exists today

### On-disk layout (authoritative on the worker node)

[task-workspace.spec.md](../specs/task-workspace.spec.md) 3.1 fixes path, key, branch, and
isolation:

- Host: `<agent group dir>/task-workspaces/<task id>`, where the group dir is
  `groups/<folder>` under the NanoClaw working directory inside
  `<instances_root>/<instance id>` (`task-workspace.spec.md:37-39`).
- Container: `/workspace/agent/task-workspaces/<task id>` via mount of the group dir at
  `/workspace/agent` (`task-workspace.spec.md:40-41`).
- Key is task id (all attempts on one instance share one directory) (`task-workspace.spec.md:42-43`).
- Branch `argus/task-<first 8 hex of task id>` (`task-workspace.spec.md:46-47`).
- Workspaces root and each workspace are mode `0700` (`task-workspace.spec.md:50-51`); the channel
  creates the root with `0o700` (`integrations/nanoclaw/argus-workspace.ts:196-196`).

Implementation mirrors the spec: `taskWorkspacePath`, `taskWorkspaceContainerPath`, `taskBranch`,
`maxWorkspacesFromEnv`, `prepareTaskWorkspace` (`integrations/nanoclaw/argus-workspace.ts:42-55`,
`:97-100`, `:140-142` in spec §6).

Checkpoints live under `ARGUS_CHECKPOINT_DIR` (or `checkpointRoot`): `<store>/<task id>/<checkpoint
id>/` with hash-verified manifest (`task-checkpoint.spec.md:40-52`, `:59-60`). Neither path is
written to SQLite today ([task-workspace.spec.md](../specs/task-workspace.spec.md) 2: "No schema
change"; [task-checkpoint.spec.md](../specs/task-checkpoint.spec.md) 5: "no schema change").

**Plain summary:** the **host workspace path**, the **checkpoint store path**, and **whether a
checkpoint object exists on disk** are **not** stored in Argus. The only WIP-shaped signal in the
contract is continuation **`wip`** (optional `ref`). Today a saved checkpoint ref reaches the API
only if something writes `wip` through observations; the channel does **not** do that after
`checkpointAfterAttempt` (`task-checkpoint.spec.md:188-189`).

Task row fields useful for ownership without new columns: `assignee_agent_id`, `attempt`,
`lease_expires_at`, `required_capabilities`, `continuation` (`tasks.py:463-522`, `routes.py:276-280`).

## Design proposal

Goal ([draft §4](../drafts/2026-10-29.task-operations.draft.md), lines 94-108): in the **task detail
view**, show **current workspace owner**, **location** (safe fields only), and **changes /
checkpoint** each as **`available` | `unavailable` | `unknown`** (plus **`not_applicable`** where
the task is not `repository:write`). Prefer **one derived read** on existing tables/events; add
columns only where no authoritative fact exists.

### Owner (no new state)

Distinguish two roles:

1. **Current attempt owner** — who holds the live claim: `tasks.assignee_agent_id`, `tasks.attempt`,
   `tasks.lease_expires_at`, joined to `agents` (`state`, `name`, `instance_id`) and
   `instances` (`pool`, `state`). Same facts as the facts grid today (`TaskDetail.tsx:191-208`) plus
   instance metadata (today only via agent drawer / fleet APIs, [live-work.spec.md](../specs/live-work.spec.md) (`:12-16`).

2. **Last work attempt** — for finished or lost workers: newest `task_attempts` row (or the attempt
   that last `PUT` changes / last `wip.observed_at`) with its `agent_id` and `claimed_at`. Derived
   from `task_attempts` + `task_changes.received_at` + `continuation.wip.observed_at`; no new table.

Always render **`observed_at`** (and **`attempt`**) beside any WIP/changes/checkpoint-derived line.
Mark **`stale`** when `observation.attempt != tasks.attempt`, or assignee agent `state` ∈
`{gone, lost}` while still showing last known facts (see § Clarified behavior).

### Location (API shape; never host path)

[worker-read-scope.spec.md](../specs/worker-read-scope.spec.md) narrows worker reads to leased work;
it does not define workspace fields yet, but [task-changes.spec.md](../specs/task-changes.spec.md)
forbids host git reads (2: `:31-34`) and the dashboard must use the API only ([AGENTS.md](../../AGENTS.md)
dashboard rule; draft §4: `:105-105`).

**Rule:** `GET /api/tasks/{id}` (detail projection) must **never** return a host filesystem path
(`<instances_root>/…/task-workspaces/…` or `ARGUS_CHECKPOINT_DIR/…`). Reasons:

- Host paths sit under **`0700`** group dirs and checkpoint stores (`task-workspace.spec.md:50-51`,
  `task-checkpoint.spec.md:131-132`) — credential-adjacent layout, not needed for operators who
  already have instance id + task id + pool config on the host ([worker-lifecycle.spec.md](../specs/worker-lifecycle.spec.md)
  3.8 `:577-578`).
- GitHub/task-changes flows never expose a workspace path ([task-changes.spec.md](../specs/task-changes.spec.md)
  2); echoing one to managers adds IDOR surface without enabling inspection (bytes stay on the
  node).

**Proposed `workspace` object** (managers; assignee worker may see a subset per worker-read-scope
update):

```json
{
  "workspace": {
    "kind": "nanoclaw_task_git",
    "present": "yes|no|unknown",
    "container_path": "/workspace/agent/task-workspaces/<task-id>",
    "branch": "argus/task-<8hex>",
    "instance_id": "<uuid|null>",
    "node_id": "<string|null>",
    "visibility": "manager"
  }
}
```

- `container_path` and `branch` are **deterministic** from task id (spec 3.1), not read from disk.
- `instance_id` from current attempt owner's `agents.instance_id` (or last work attempt when stale).
- `present`: optional coarse signal from heartbeat `observation.workspace` (`stall-visibility.spec.md:120-121`) while claimed; **`unknown`** when no fresh observation or agent not live — not proof of absence.
- `node_id`: only when recorded (future `wip` ref save includes manifest `node_id`, `task-checkpoint.spec.md:57-58`) — **not** hostname of arbitrary hosts.

**No migration** for location if the API computes the above from task id + assignee join + optional
`tasks.observation`. A **migration** would only be needed if operators require **persisted**
last-known `node_id` / `present` after heartbeat clears on expiry (`stall-visibility.spec.md:128-129`) —
prefer storing that in **`continuation.wip`** or a small JSON column on `task_attempts.outcome`
metadata in a later spec if replay after terminate matters.

### Per-item states (changes & checkpoint)

Never collapse to boolean false. Use:

| State | Meaning |
| --- | --- |
| `available` | Argus has positive evidence |
| `unavailable` | Argus knows the item cannot be served for that attempt |
| `unknown` | No evidence yet, or evidence too stale to assert |
| `not_applicable` | Task lacks `repository:write` (no workspace/checkpoint/changes pipeline) |

**Changes** (`task-changes.spec.md`):

| State | Rule |
| --- | --- |
| `not_applicable` | `repository:write` ∉ `required_capabilities` (`task-changes.spec.md:42-42`) |
| `available` | Row in `task_changes` for `(task_id, attempt)` (`0052_task_changes.sql:4-18`) |
| `unavailable` | Attempt `< tasks.attempt` or attempt ended (`released`/`complete`/`fail`) and no row |
| `unknown` | Current attempt in flight, assignee live, no row yet (relay lag, delegate silent, or engine without delegate — spec 4 open `:162-165`) |

**Checkpoint**:

| State | Rule |
| --- | --- |
| `not_applicable` | Not `repository:write` or checkpoints off (no `ARGUS_CHECKPOINT_DIR`) (`task-checkpoint.spec.md:40-42`) |
| `available` | `continuation.wip.ref` matches `checkpoint:<id>:<sha256>` **or** (future) API records ref from worker observation with matching `node_id` |
| `unavailable` | Attempt needs pinned ref (`task-checkpoint.spec.md:96-98`) but contract has no matching ref and attempt blocked `env_checkpoint_unavailable` — surfacing via `block_reason` |
| `unknown` | **Honest default today** for all tasks: save does not report ref (`task-checkpoint.spec.md:188-189`). Retention pruning (newest 3 per task, `:152-153`) can race with `available` even after reporting — treat as open |

**Minimal producer prerequisite:** after successful `checkpointTaskWorkspace`, `POST
/tasks/{id}/observations` with `wip: { summary, ref: saved.ref, provenance: worker_reported,
observed_at }` (closes `task-checkpoint.spec.md` §4). No store path in the body.

### Why the dashboard cannot probe the filesystem

Workspaces and checkpoint bytes live on the **worker node's** local filesystem ([single-node.spec.md](../specs/single-node.spec.md)
8-15: one Argus process/SQLite; fleet elsewhere). The dashboard talks to Argus only
([AGENTS.md](../../AGENTS.md)). Any "is the checkpoint file there?" check would require host-side
git or directory reads, which [task-changes.spec.md](../specs/task-changes.spec.md) 2 forbids for
worktrees and [task-workspace.spec.md](../specs/task-workspace.spec.md) 3.4 limits host access to
read-only validation during preflight — not an operator probe API. The API can only report what a
worker (or its host relay) **already told** Argus.

## Clarified behavior (draft §4 cases)

### Worker disappears

When the assignee agent ends (`gone`/`lost`, `agents.state` `0003_agents.sql:7-7`) or the instance
reaches `terminated` (`0011_fleet.sql:25-30`):

- **Owner shown:** last attempt's `task_attempts.agent_id` + `instances.state` for that agent's
  `instance_id`.
- **Workspace:** presumed to have existed on that instance's group dir ([task-workspace.spec.md](../specs/task-workspace.spec.md)
  3.2 `:70-71`); after terminate, bytes are unreachable from a live worker — `present: unknown` or
  `no` if cleanup removed the directory ([workspace-cleanup.spec.md](../specs/workspace-cleanup.spec.md)
  3.2 `:60-69`, WIP rules §3.5 `:184-238`).
- **Changes:** `unavailable` for the lost attempt once relay cannot run (no live assignee); last
  snapshot remains `available` if row exists (`task-changes.spec.md:127-127`).
- **Checkpoint:** `unknown` unless `wip.ref` was recorded; restore remains **node-local**
  (`task-checkpoint.spec.md:16-19`, `:187-189`). Copy: recoverable only where the checkpoint **store**
  on that node survives — not inspectable through Argus.

Cross-ref [workspace-cleanup.spec.md](../specs/workspace-cleanup.spec.md) 3.5: terminated-instance
WIP is archived or blocks cleanup; task workspaces inside the instance dir are in scope
([task-workspace.spec.md](../specs/task-workspace.spec.md) 3.3 `:89-92`).

### Work on another instance (still one Argus)

"Remote" means another **`instances` row** / container under the same SQLite ([single-node.spec.md](../specs/single-node.spec.md)
13-15), not a second Argus. Ownership fields (`assignee`, `attempt`, `instance_id`, grants) stay
authoritative in the API. The view must **not** imply Argus can read workspace or checkpoint bytes —
only metadata relayed via `task_changes`, `wip`, and heartbeat `observation`.

### Reported owner is stale

**Definition:** stale when any of:

- Shown `attempt` ≠ `tasks.attempt` (claim moved: retry, release, new claim).
- Shown `wip` / changes snapshot `attempt` ≠ `tasks.attempt`.
- `observed_at` (or changes `at`) is older than the current claim's `claimed_at` from
  `task_attempts`.
- Owner agent `state` not in `{active, draining}` while task still `claimed` by someone else.

**UI rule:** label **Stale**; never present stale lines as current owner/location. Follow
[stall-visibility.spec.md](../specs/stall-visibility.spec.md) precedent: observation before current
claim treated as unknown for stall (`:130-132`); same fence for ownership observations.

## Success criteria

Testable operator outcomes matching draft **Success:** (`2026-10-29.task-operations.draft.md:107-108`):

1. On a `repository:write` task with a live assignee, the detail view names **agent**, **attempt**,
   **instance/pool**, deterministic **container path** and **branch**, and whether **changes** are
   `available` / `unknown` / `not_applicable`.
2. After a failed attempt with checkpoint save on disk but **no** `wip` ref, the view shows
   checkpoint **`unknown`** and explains that recovery depends on the node store, not dashboard/API
   inspection.
3. After worker loss or instance `terminated`, the view shows **stale** or **last** owner with
   **`unavailable`/`unknown`** for live inspection, without exposing host paths.
4. A manager never receives `ARGUS_CHECKPOINT_DIR` or `<instances_root>/…` in JSON; a worker token
   receives at most lease-scoped fields ([worker-read-scope.spec.md](../specs/worker-read-scope.spec.md)).
