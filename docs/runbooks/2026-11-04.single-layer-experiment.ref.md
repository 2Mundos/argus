# Single-layer experiment: running the P7 A/B

This runbook is how an operator runs the A/B in the
[single-layer experiment](../specs/single-layer-experiment.spec.md). It has not
been run, and **no experiment result exists**. Tests and fixtures in the repository
are not results. Record a real run in a dated report under `docs/reports/` and link
it from `docs/README.md`.

What is **not** automated: nothing schedules paid runs, picks tasks, merges pull
requests, deploys, or decides the outcome. The operator does each of these by hand.

## Budget and size

- **Size.** 20 tasks, 10 per arm, balanced by difficulty. With fewer than 16
  finished tasks, stop and report "no decision".
- **Budget cap.** Set a total cap in dollars before you start, and write it in the
  report. Give every assigned task a `budget_usd` of the cap divided by 20, so no
  task can take more than its share ([task cost](../specs/task-cost.spec.md)). Use
  the same per-task budget in both arms.
- **Cheapest models.** The arms use the policy's normal tiers. Do not raise a
  tier for the experiment.

## Preconditions

- A disposable or low-risk node with Claude accounts in the pool, and test or
  low-stakes repositories. Credentials stay in the gateway. Nothing is pasted into
  chat, logs or the assignment file.
- The host runs the current channel (`integrations/nanoclaw/install.sh`), and
  `integrations/nanoclaw/provision.sh check` passes, including
  `argus-single-layer.test.ts`.
- The model policy has a Claude chain for `implementation` and
  `hard_implementation`. Without one, every single-layer claim falls back with
  `no_implementation_chain`.
- About 40 comparable coding tasks that are not yet claimed. Each must have a
  repository and a difficulty, and pin no harness or executor model. Create them
  with `requires_approval`, so they wait in `awaiting_approval` until step 3.

## 1. Assign

Export the candidates as `[{"id": …, "difficulty": …}, …]`, choose a new experiment
id and a seed, and write both in the report before you look at any task:

```bash
scripts/single_layer_ab.py assign --candidates candidates.json \
  --experiment p7-1 --seed "$SEED" --size 20 -o assignment.json
```

Check the arms and strata in `assignment.json`. Do not edit it by hand. A different
seed is a different experiment. Candidates that were not selected are not in the
experiment. Approve or cancel them as usual.

## 2. Turn the flag on

Put `assignment.json` where the host process can read it. Under the `nanoclaw`
runtime that is the instance directory, because the host mounts only that. Then set
these in the pool's `env`:

```text
ARGUS_SINGLE_LAYER=claude
ARGUS_SINGLE_LAYER_ASSIGNMENT=<path inside the host>
```

Restart the host: the flag is read only at start. If the log shows "Single-layer
experiment refused", the flag is off. Fix the value before you continue.

## 3. First claims

Approve one task of each arm. Before approving the rest, check:

- The harness model selection of each claim has the marker
  `single-layer experiment p7-1: arm=<arm>` and no `fallback=`.
- The single-layer claim's `model-policy-attempt-1.json` names an implementation
  tier model and has an `experiment` block.
- When the single-layer task opens a PR, a `pr_opened` milestone appears.

If any check fails, stop (rollback below) and fix the cause before going on.

## 4. Run

Approve the remaining tasks. Review and merge each PR by the project's normal
rules, without knowing or using the arm. Do not retry or cancel a task because of
its arm.

## Stop conditions

Stop the experiment (rollback) when any of these happens:

- Spend reaches the budget cap, as read on the Cost tab.
- A single-layer attempt calls `argus-delegate` or another coding CLI, or touches a
  repository other than the task's.
- A secret appears in a log, a reply or an artifact.
- More than a quarter of the single-layer claims fall back. The arm is then not
  being tested.
- Any harm to the node or to other agents' work.

## Rollback

Unset `ARGUS_SINGLE_LAYER` in the pool's `env` and restart the host. Every claim,
including the remaining assigned tasks, then runs the default path. Tasks in flight
finish their attempt as they started. Nothing in the database needs undoing.

## 5. Analyze

Work on a copy of the database, never the live one. Then collect merge times from
the forge as `{"<pr url>": "<merged_at ISO time>"}` for the experiment's PRs:

```bash
scripts/single_layer_ab.py export --db copy-of-argus.db \
  --assignment assignment.json -o attempts.jsonl
scripts/single_layer_ab.py analyze --attempts attempts.jsonl \
  --assignment assignment.json --merged merged.json -o report.json
```

Read the output per assigned arm. Before any figure, report the `unknown` usage and
`censored` time counts, the fallbacks and the balance. A median with
`median_biased_low` is a lower bound. `cost_usd` is the cost the provider reported,
which is often null for subscription accounts. For an estimate at API rates, use
the Cost tab per task.

The decision is a human one, and goes in the report with the figures. Either change
[engines](../specs/engines.spec.md) in a spec PR, or remove the arm. Then turn the
flag off.
