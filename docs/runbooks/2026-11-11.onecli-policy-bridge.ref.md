# OneCLI policy bridge failure: tasks blocked `env_repository_unreachable`

This runbook is for an operator whose tasks block because the OneCLI gateway attached no
credential to repository requests. The preflight behaviour is in the
[failure classes spec](../specs/failure-classes.spec.md) (3.3.1, "Bounded re-arms"). Argus
does not patch OneCLI's code or database; the fix is operational, and the durable one is
upstream.

## Symptom in Argus

- A task is blocked with `env_repository_unreachable`.
- Its error starts `repository preflight unknown:` or `repository preflight forge_denied:`
  and ends with `rearm_exhausted` text: the OneCLI policy rule stayed unpublished after 4
  re-applications of the repository lease. The tail says the gateway attached no credential,
  how many times the lease was re-applied and within how many seconds, and that it is a OneCLI
  policy-publish fault, not a permission or network problem.
- The `repository_preflight` evidence event shows `diagnosis: rearm_exhausted`,
  `fault: gateway_policy_publish`, `injection: absent`, probe `authentication: unknown` and
  `permissions: absent` (a public 200 or a 404), `rearm_attempts` and `rearm_window_ms`.

A permission or network problem looks different (`forge_denied` with a proven credential,
`network_failure`), so do not rotate tokens or change repository access for this symptom.

## Detection on the host

```bash
docker logs onecli 2>&1 | grep -E 'policy coherence bridge failed|injections_applied=0'
```

Matches repeating about every 5 s while tasks preflight confirm this runbook applies.

## Root cause

Each lease re-application invalidates the gateway cache and makes OneCLI rematerialize its
policy rules. The rematerialize runs in one interactive Prisma transaction, which has a
5000 ms limit. With a large `policy_rules_v2` table (6,541 live and 1,182 dead rows, 6.5 MB,
on 2026-11-11) or under contention it overruns, and every re-application fails with:

```
WARN policy coherence bridge failed
  PrismaClientKnownRequestError P2028
  prisma.policyRuleV2.create()
  "Transaction already closed: A query cannot be executed on an expired transaction.
   The timeout for this transaction was 5000 ms"
```

The rule is never published, so the gateway forwards requests with `injections_applied=0`.
Argus backs off with jitter, bounds the re-application window and shares one round between
concurrent preflights so it does not add to the storm, but it cannot publish the rule itself;
it fails closed instead of running unauthenticated.

## Remediation

1. Restart the gateway: `docker restart onecli`. Wait until it is healthy, then check that
   the log grep above stops matching.
2. Upstream: raise OneCLI's interactive transaction timeout for the rematerialize
   transaction (and prune dead `policy_rules_v2` rows). This is documented here and **not**
   patched in this repository.

## Follow-up

Blocked tasks do not retry on their own. After the gateway is healthy, unblock each affected
task so it runs the preflight again.
