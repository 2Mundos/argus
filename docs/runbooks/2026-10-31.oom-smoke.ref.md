# OOM evidence: Docker smoke

The tests for [OOM evidence](../specs/failure-classes.spec.md) (3.2.1) use a fake
`docker inspect`. They do not prove that a real daemon reports
`State.OOMKilled=true` and exit code `137` for a kernel OOM kill, or that the channel's
reader (`readSessionEvidence` in `integrations/nanoclaw/argus-stderr-tail.ts`) parses
that answer as an OOM kill. This runbook checks both on one disposable container. It
has not been run yet; record the result in a report.

## Safety

- Only the disposable container `argus-oom-smoke` created below. Never a live worker,
  a NanoClaw host or session container, or any other running container.
- Nothing host-wide: no daemon config, cgroup, sysctl or pool quota changes. The
  memory cap is the probe's own `--memory 64m --memory-swap 64m`.
- The allocator is bounded (at most 256 MiB requested) and has a hard 20 s timeout.

**Deviation: no `--rm`.** `--rm` removes the container as it exits, before
`docker inspect` can read its state, so the probe runs without it and step 4 removes
it with `docker rm`. Do not skip step 4.

## Before you start

- A Docker CLI on a host where disposable containers are allowed.
- Node 22 and this repository checked out (for `scripts/oom-evidence.ts`).
- No container named `argus-oom-smoke` (`docker ps -a --filter name=^argus-oom-smoke$`).

## 1. Trigger an OOM kill

```bash
docker run --name argus-oom-smoke \
  --memory 64m --memory-swap 64m --pids-limit 64 \
  alpine:3.20 sh -c 'timeout -s KILL 20 sh -c "head -c 256m /dev/zero | tail"'
docker inspect --format '{{.State.OOMKilled}} {{.State.ExitCode}}' argus-oom-smoke
```

Expect `true 137`. `tail` holds its input in memory until EOF, so it goes past 64 MiB
and the kernel kills it. If `timeout` fires first, the answer is `false 137`. In that
case the host did not OOM-kill the probe: report it and do not raise the limits.

## 2. Feed it through the channel's reader

```bash
node --experimental-strip-types scripts/oom-evidence.ts argus-oom-smoke
```

Expect `"oomKilled":true`, `"exitCode":137`, `"container":"argus-oom-smoke"` and
`"oom_kill":true`. That is the value the channel would send on `session_lost`. The
script runs only `docker inspect` and `docker logs` on that container.

## 3. Negative control: a plain kill

```bash
docker rm argus-oom-smoke
docker run -d --name argus-oom-smoke --memory 64m --memory-swap 64m --pids-limit 64 \
  alpine:3.20 sleep 20
docker kill argus-oom-smoke
docker inspect --format '{{.State.OOMKilled}} {{.State.ExitCode}}' argus-oom-smoke
node --experimental-strip-types scripts/oom-evidence.ts argus-oom-smoke
```

Expect `false 137` and `"oom_kill":false`. SIGKILL alone gives exit code 137, so the
exit code by itself is not OOM evidence.

## 4. Clean up

```bash
docker rm -f argus-oom-smoke
```

## Record

Note the date, the Docker and kernel versions (`docker version`, `uname -r`), the cgroup
version (`stat -fc %T /sys/fs/cgroup`) and the four outputs above in
`docs/reports/YYYY-MM-DD.oom-smoke.ref.md`.
