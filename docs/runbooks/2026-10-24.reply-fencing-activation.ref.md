# Reply fencing: activation and containment

Fixes cross-task contamination in the NanoClaw channel (late output of task A applied
to task B; see `task-continuation.spec.md` 3.5 and 3.8). Merging the PR changes
nothing on a running fleet: the API change needs an Argus restart and the channel
change needs a NanoClaw reinstall on the worker host. Neither is automatic.

## Containment before activation

1. Do not cancel, accept or edit live tasks to test this. Keep workspaces and history.
2. A worker that asked for assistance (`ASSIST`/`ASK`) and then claimed another task
   is the risky state. Prefer letting that worker go idle, or recycle its runtime when
   it is between tasks, before it claims again. Do not reboot healthy workers.
3. Review rather than accept any result whose summary or checklist ids do not match
   its task (the decision inbox shows the checklist ids per task).

## Activation (operator, manual)

1. Merge the PR (separate authorization).
2. API (desktop-i9, `argus-preview.service`): update the checkout and restart the
   service. Check: completing a task with a foreign checklist id returns 422
   `checklist_mismatch` (the regression `test_checklist_ids_of_another_task_are_rejected`).
3. NanoClaw: reinstall the overlay (`integrations/nanoclaw/install.sh`, or
   `provision.sh` with `ARGUS_NANOCLAW_ENGINES=1`) and restart worker groups one at a
   time, only when idle. Check the worker log for no `dropped a reply` warnings on a
   normal run.

## Verification after activation

- A worker's second task text contains `[Argus reply scope]` and its replies start
  with `COMPLETE on <task-id>:`; a first task after a recycle does not.
- `Argus channel dropped a reply that is not provably this task's` in a worker log is
  the fence working; `reason` says why. A task stuck after three scope reminders
  times out and is retried by Argus with no attempt consumed wrongly.

## Rollback

Reinstall the previous overlay and restart the workers; revert the API and restart.
No schema change, no data migration, nothing to undo in the database.
