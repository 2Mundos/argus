# Workspace cleanup: operator guide

How to turn on the cleanup of terminated NanoClaw instance directories
(`<nanoclaw.instances_root>/<instance id>`) safely. The behaviour is defined in
[workspace-cleanup.spec.md](../specs/workspace-cleanup.spec.md). Cleanup is off
by default and dry run is the default mode; merging the code changes nothing on
a running host.

## Before you start

- Cleanup only acts on pools whose Docker target is a local unix socket that
  shares the filesystem with Argus. Remote daemons, Docker Desktop and
  Kubernetes pools are skipped and listed under the run's `skipped`.
- Choose an archive root on a filesystem with room to spare. It must be an
  absolute, real directory (not a symlink) that is neither inside an instances
  root nor contains one. Argus never deletes from it; prune old archives by hand.
- Install `git` on the Argus host. Without it, every instance with a repository
  is blocked with `git_missing`.

## 1. Dry run with cleanup still disabled

A dry run never renames, archives or deletes. It works while cleanup is disabled.

```bash
curl -s -X POST -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"dry_run": true, "wait_s": 30}' "$ARGUS/api/fleet/workspace-cleanup/run" | jq
curl -s -H "Authorization: Bearer $TOKEN" \
  "$ARGUS/api/fleet/workspace-cleanup/instances?status=blocked" | jq
```

The MCP tools `run_workspace_cleanup` (dry run by default), `get_workspace_cleanup`
and `list_workspace_cleanup` do the same, and the Fleet tab has a
"Workspace cleanup" card with a "Dry run now" button. A run handles at most
`MAX_INSTANCES` directories, so repeat the dry run to see the whole backlog.

Read the result:

- `eligible` / `wip_found`: will be archived, then deleted.
- `eligible` / `no_wip`: will be deleted with no archive.
- `blocked`: a safety check stopped it; the reason says which (table below).
- `preserved`: not eligible (not terminated, too recent, unknown, not a UUID).
- `bytes_estimated` vs `bytes_freed` are approximate: allocated blocks,
  hardlinks counted once, and the `statvfs` delta around each deletion.

## 2. Enable

Set in the Argus environment and restart Argus:

```bash
ARGUS_WORKSPACE_CLEANUP_ENABLED=true
ARGUS_WORKSPACE_CLEANUP_ARCHIVE_ROOT=/srv/argus-archive   # example path
# ARGUS_WORKSPACE_CLEANUP_DRY_RUN stays true: the loop keeps reporting only
```

Then run one real cleanup by hand (admin token only) and check the result:

```bash
curl -s -X POST -H "Authorization: Bearer $ADMIN_TOKEN" -H 'Content-Type: application/json' \
  -d '{"dry_run": false, "wait_s": 30}' "$ARGUS/api/fleet/workspace-cleanup/run" | jq
```

When you trust the results, set `ARGUS_WORKSPACE_CLEANUP_DRY_RUN=false` and restart
so the hourly loop deletes too. Other settings (age, interval, budgets, retries,
low-disk floor, git timeout) are listed in spec 3.1.

## Reason codes

| Reason | What to do |
| --- | --- |
| `archive_root_unset`, `archive_root_invalid` | Set a valid archive root (see above) |
| `low_disk` | Free space under `LOW_DISK_BYTES`: only caches in clean repos were pruned. Free space elsewhere first |
| `archive_no_space`, `archive_permission`, `archive_too_large` | Fix the archive root, or raise `MAX_ARCHIVE_BYTES` |
| `archive_error`, `archive_hash_mismatch`, `archive_timeout`, `git_error`, `git_missing` | Check the archive disk and git; the next run retries |
| `unsupported_repo`, `scan_limit`, `unsafe_path`, `unreadable` | Inspect the directory by hand |
| `agent_active`, `task_claimed`, `state_changed` | The instance is in use again: nothing to do |
| `container_mount` | A container (running or stopped) mounts it: remove the stopped container |
| `container_check_unavailable`, `mounts_unreadable`, `db_error` | Argus could not prove it is unused; check Docker and `/proc` |
| `mount_present`, `process_reference`, `shared_path` | Something lives in or uses the directory: inspect it |
| `permission_denied` | Files owned by another uid: fix ownership or remove by hand |
| `max_attempts` | The loop gave up after `MAX_ATTEMPTS`; a manual run tries again |
| `internal_error` | A bug: the directory was put back. Check the Argus log |

A `failed` row (`delete_interrupted`, `delete_error`) means deletion started;
the archive, if any, is already complete, and the next run finishes the
`.argus-gc-<id>` tombstone.

## Restore

Every archive lives in `<archive_root>/<instance id>/<run id>/` with a
`manifest.json`. Restore into an empty directory:

```bash
cd apps/api && uv run python -m argus_api.fleet.workspace_restore \
  /srv/argus-archive/<instance id>/<run id> /tmp/restored
```

Each repository comes back with its local commits, staged and unstaged changes,
and untracked files. Sensitive files (`.env*`, keys, `.ssh`, …) were never
archived; the manifest lists them under `skipped_sensitive`.

## Limitations

- NanoClaw state outside git repositories (conversations, logs) is not archived.
- Committed secrets stay in the bundle (`sensitive_in_commits` lists them).
- Repository-configured clean/smudge filters still run during the diff.
- Untracked files inside a repository's `node_modules`, `build`, `dist`, … are
  treated as regenerable and not archived.
- Folders with no instance row are never deleted; remove them by hand.

## Rollback

Unset `ARGUS_WORKSPACE_CLEANUP_ENABLED` and restart. The migration only adds
tables; deleted directories come back only from their archives.
