# Independent review gate failures and manual acceptance

This runbook records what happened when `review.independent` was first used for real on
project argus, and how to diagnose and act on a parent task stuck in `in_review`.

## How it works

With `review.independent` mode other than `off`, a parent task that delivers code moves to
`in_review`, and Argus spawns a `code_review` child pinned to a reviewer chosen by
`execution.chains` (or the model policy), excluding every model, provider and account of the
author. See [independent code review](../specs/settings.spec.md) section 3.5.

## Symptoms and causes

| Symptom | Cause | Current behaviour |
|---|---|---|
| Child fails 3 times; its `stderr-tail` artifact shows `401 token_expired` | The provider login expired | Renew the provider login. The account moves to a login-required state and the gate fails over to the next alternative |
| Child fails with `422 result.data does not match its kind's schema` | The reviewer put `verdict`, `findings` or `head_sha` outside `data` | Top-level review keys are normalised into `data` (`review.result_normalised`). Keys that do not fit are named in the error details |
| Parent `in_review` with `block_reason: no_review_head` | The head commit could not be resolved from the task record or the forge | One open `review` decision: `retry_reviewer`, `approve_without_review` or `cancel` |
| Parent `in_review` with no open decision (older builds) | The reviewer was gone and no decision was opened | A startup repair opens the manual `review` decision (`review.decision_backfilled`) |

## Diagnosis (read-only)

```bash
# Global value and its source (env | global | default); project value and source
curl -s http://127.0.0.1:8000/api/settings | jq '.settings[] | select(.key=="review.independent" or .key=="execution.chains")'
curl -s http://127.0.0.1:8000/api/projects/<slug>/settings | jq '.settings[] | select(.key=="review.independent" or .key=="execution.chains")'

# Parent events: review.independent_requested, review.independent_blocked,
# review.independent_child_failed, review.independent_skipped
curl -s 'http://127.0.0.1:8000/api/events?subject_type=task&subject_id=<id>'

# Child failure reason: the stderr-tail artifact of the failed child
curl -s http://127.0.0.1:8000/api/tasks/<child_id>/artifacts | jq '.[] | select(.name=="stderr-tail")'

# Selected reviewer, fallbacks and skipped alternatives
curl -s http://127.0.0.1:8000/api/tasks/<id>/route
```

Read the parent's `review.independent_child_failed` events for `error_class`, `account`,
`model` and `alternative`. The `review.independent_selected` event records the chain
source and why each alternative was skipped.

## Operator actions

### Switch the project override off or on

Removing the project override returns to the global value (`off` by default):

```bash
curl -s -X DELETE http://127.0.0.1:8000/api/projects/<slug>/settings/review.independent
```

Turn it on for the project:

```bash
curl -s -X PUT http://127.0.0.1:8000/api/projects/<slug>/settings/review.independent \
  -H 'content-type: application/json' \
  -d '{"value":{"mode":"different_provider","max_rounds":3}}'
```

Changing the setting cancels the running reviewer of every `in_review` parent in a project
where it is now `off`. Those parents get a `gate_disabled` manual decision.

### Answer the manual review decision

Find the open decision in the inbox (`GET /api/inbox`), then answer it:

```bash
curl -s -X POST http://127.0.0.1:8000/api/decisions/<decision_id>/answer \
  -H 'content-type: application/json' \
  -d '{"choice":"accept","text":"<reason>"}'
```

- `accept`: the work passes the review gate.
- `accept_with_deviation`: the work passes over unmet acceptance items, which stay
  `verification_missing`. `text` is required and names the deviation.
- `reject`: the task does not pass the gate. Put the reason in `text`.

Answering clears the gate `block_reason`. Always put the reason in `text`.

## Rules

- Never edit the database to clear a gate. Use the endpoints above, so the audit events exist.
- Renew provider logins through the account flow, not by copying credentials.
- Do not turn the gate on for a project to unblock one task. Answer its decision instead.
