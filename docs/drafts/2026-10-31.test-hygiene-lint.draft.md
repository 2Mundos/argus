# Test hygiene checks

Status: draft · 2026-10-31

## Context

The test suite runs with `pytest -n auto` on every push. Tests that wait on wall
time are slow and flaky under parallel load: there are 67 `sleep(` calls under
`apps/api/tests` today (some are inside fake scripts and are fine). The rule
"use `tx.now`, never a clock read elsewhere" is written in AGENTS.md but is not
checked. Skips and lint suppressions can land without a reason.

## Proposal

Add `scripts/check_tests.py`, a small AST check run from `make lint` next to
`validate_docs.py`. It reports:

1. `time.sleep` / `asyncio.sleep` with a non-zero argument in test code. Await
   the event, future or queue that marks the milestone instead.
2. Loops that poll a condition and sleep between checks.
3. Elapsed-time assertions: `time.time()`, `time.monotonic()` or
   `datetime.now()` deltas in tests. Assert on events and counts.
4. Per-test timeouts and retry markers. Flaky tests are fixed, not retried.
5. `pytest.mark.skip` / `skipif` / `xfail` without a `reason=`, and `# noqa`,
   `# type: ignore` or `biome-ignore` without a written reason.
6. In application code, `datetime.now()` / `time.time()` inside a function that
   receives a `Tx`. Use `tx.now`.

An exception is one comment on the line above that names why
(`# check-tests: allow sleep — fake CLI must outlive the poll`). Fake scripts
written as strings are not test code and are not scanned.

The same rules for the dashboard (no `setTimeout` waits or
`requestAnimationFrame` in Vitest) can follow in Biome config or a second pass
of the script.

## Rollout

1. Land the check in report-only mode and list current hits.
2. Fix or annotate them, file by file, starting with the slowest tests.
3. Make the check fail `make lint`.

## Success

`make lint` fails on a new test that sleeps or retries, and the suite's slowest
tests no longer wait on wall time.

## Open questions

- Ruff has no plugin API. Is a standalone AST script enough, or should the
  test-side rules run as a pytest plugin that fails at collection?
- Should rule 6 cover every module under `argus_api`, or only functions that
  receive a `Tx`?

## Out of scope

Rewriting existing integration scripts (`scripts/*-e2e.sh`), which run real
processes and may wait on real time.
