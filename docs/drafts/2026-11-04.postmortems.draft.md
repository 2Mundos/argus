# Postmortems

Status: implemented · 2026-11-04 (template in `docs/templates/postmortem.md`, rule in `AGENTS.md`, indexed in `docs/README.md`, inaugural postmortem `docs/postmortems/2026-11-04.launcher-instance-permission.ref.md`)

## Context

Argus records what it decided (specs, drafts) and what it checked
(`docs/reports/`), but not why a bug got past the process. A fix lands with a
failing test, which stops that bug. It does not show why the rules, tests and
review let it through, so the same kind of bug comes back elsewhere.

The DeepSeek harness keeps `docs/postmortem/`, four so far. Each is written when
a bug was subtle, systemic (a gap in tests, tooling or conventions, not a typo)
and costly to rediscover. Each opens with a summary a reader can take in in 30
seconds and ends with the guardrails added (a test, an instruction rule, a
gate), linked. Their 0004 is what prompted the
[failure evidence audit](2026-11-04.failure-evidence-audit.draft.md).

## Proposal

1. **Location and name.** `docs/postmortems/YYYY-MM-DD.name.ref.md`. That fits
   the existing dated-name rule in `scripts/validate_docs.py` (`ref`), so no
   validator change is needed. The directory is added to the table in
   `docs/README.md` and every postmortem is linked from it, as every doc is.
2. **Template** (`docs/templates/postmortem.md`):
   - **Summary.** One paragraph: what broke, the cause in plain words, why it
     escaped, the lesson.
   - **Impact.** Who or what was affected, and for how long.
   - **Mechanism.** How the bug works, precisely enough to recognise it again.
   - **Why it escaped.** Which test, rule or review step should have caught it,
     and why it didn't.
   - **Guardrails added.** Links to the tests, `AGENTS.md` rules, spec changes or
     checks that now fail on this class of bug.
   - **Lessons.** At most four lines, each usable outside this incident.
3. **When to write one.** All three of: the mechanism is not obvious, the escape
   is a gap in process rather than a slip, and rediscovering it would cost real
   time. A one-line fix with a test does not need one.
4. **Agent rule** (one line in `AGENTS.md`, under Tests): "A bug that meets the
   postmortem bar gets one in the same PR as its fix."
5. **Living specs stay current.** A postmortem never replaces a spec edit. The
   spec states the corrected behaviour; the postmortem explains the history.

## Success

The next bug that escaped through a process gap has a postmortem whose
guardrails section names at least one new automated check.
