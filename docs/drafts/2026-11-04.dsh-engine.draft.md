# DeepSeek Harness as an engine

## Context

DeepSeek Harness (`dsh`, MIT) is an open-source agent harness from DeepSeek AI.
A local checkout lives at `~/work/deepseek-harness` (0.2.2-alpha.3). Three
things make it a candidate for Argus:

- **Headless one-shot runs.** `dsh --profile headless "task"`: the final
  answer on stdout, exit 0 when complete and 1 when aborted or errored,
  `dsh: <code>: <message>` on stderr. `--json` streams newline-delimited events,
  and `--session-id` resumes a session. It opens no ports and leaves nothing
  running. That is the interface `argus-delegate` wants from an executor.
- **OpenAI-compatible providers natively.** Our `custom` harness today runs
  Claude Code behind a Messages↔Chat Completions bridge
  ([custom harness](../specs/custom-harness.spec.md)), and `local` runs it
  against Strata's Anthropic-compatible endpoint. `dsh` talks to these
  providers directly. Its headless profile reads keys from the launch
  environment, ignores stored sign-ins, and has a sandbox and permission
  presets.
- **An ACP server.** `dsh --profile acp` serves the Agent Client Protocol over
  JSON-RPC stdio: create, resume and cancel sessions, attach MCP servers, answer
  permission prompts. ACP is not specific to dsh; one Argus ACP client could
  drive any agent that speaks it.

Risks: it is a developer preview with breaking changes promised, its safety
notice says it has had no security audit, and it needs Node ≥ 24.9 (the agent
image is on Node 22).

## Proposal

Two steps; the second waits for evidence from the first.

1. **Executor `dsh`, off by default.**
   - `argus-delegate dsh` runs `dsh --profile headless --json` on an executor
     lease for a `custom` or `local` account. `base_url`, `model` and the key
     come from the lease `settings`, and the key only through
     `ARGUS_ACCOUNT_API_KEY`, as for OpenCode
     ([engines](../specs/engines.spec.md)).
   - The pinned version is installed in the tools layer under its own Node
     runtime, so the image's Node 22 is untouched.
   - Readiness follows the existing three facts: `installed` (pinned version
     reported), `authenticated` (an account usable by the container),
     `validated` (`smoke.sh` runs one cheap task).
   - It is off until an operator enables it in settings; no account prefers it
     by default.
   - It runs inside the worker container, under Argus's existing isolation.
     dsh's own sandbox is an extra layer, never the one we rely on.
2. **Harness through ACP, later.** If the executor runs well, evaluate an ACP
   provider in NanoClaw (the harness role) for dsh. Count it a success only if
   it also runs one other ACP agent unchanged. Otherwise it is a one-engine
   adapter and isn't worth the cost.

## Cover every surface

- **Entry points.** The engine catalogue (`GET /api/engines`, MCP
  `list_engines`) lists `dsh` with its layers and readiness. Routing
  (`route_task`) only picks it when enabled.
- **Engines.** This adds a seventh engine. The others are unchanged.
- **Contracts.** The engine entry needs a new value in the API models;
  `make openapi`.
- **Way back.** Disabling it in settings stops new leases. Running delegations
  finish.
- **Docs.** `engines.spec.md` gains the row. `custom-harness.spec.md` is
  unchanged unless step 2 replaces the bridge.
- **Failure classes.** Its stderr codes (`dsh: <code>:`) are a new evidence
  source and follow the
  [failure evidence audit](2026-11-04.failure-evidence-audit.draft.md) rule,
  with recordings per
  [engine transcript replay](2026-11-04.engine-transcript-replay.draft.md).

## Success

One week of `custom`-account delegations split between OpenCode and `dsh` on the
same model, compared on completion, cost and failure classes.

## Open questions

- Is `dsh` better than OpenCode for our tasks, or just different? Step 1 exists
  to answer this; without a measurable gain, drop it.
- How often does a dsh release break the headless contract (`--json` events,
  exit codes)? Pin exactly, and bump only with a re-recorded transcript.
- Does its headless JSON stream carry token usage per call? Cost tracking needs
  it.
- Which provider routes does it ship besides DeepSeek's? OpenRouter and Strata
  must be confirmed before step 1.
