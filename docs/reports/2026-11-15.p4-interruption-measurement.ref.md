# P4 interruption measurement (2026-10-16 to 2026-11-15, UTC)

Input: read-only export `attempts-2026-10-16_to_2026-11-15.csv.gz` (sha256
`f2b6617f…8035b`, artifact 67f412a1), 1378 attempt rows over 432 tasks, one row
per `task_attempts` row claimed in the window. Counts were made with a
standard-library Python script over the CSV; no model output is involved.

## Method

- Interruption events are the export's `task.fail`, `task.block`, `task.expire`
  and `agent.lost` events inside each attempt, classified by the export as `quota`,
  `session_lost` or `other`.
- "Reached a PR" has two readings, because `pr_opened_on_task` is per task:
  - **strict:** the attempt that ended `complete` on a task with a PR (91 attempts);
  - **broad:** every attempt on a task with a PR (202 attempts, 91 tasks).
- `retried` is recorded per attempt only, so "non-retried interruption" means an
  interrupted attempt with `retried = no`.

## Counts

Interruption events (all 1378 attempts):

| kind | event | events | attempts |
|---|---|---:|---:|
| quota | `task.fail` quota | 15698 | 357 |
| quota | `task.block` awaiting_quota / quota_exhausted / quota | 1249 | 376 |
| session_lost | any (`session_lost` reason or `agent.lost`) | 0 | 0 |
| other | `task.block` waiting for decision (not a failure) | 1141 | 681 |
| other | `task.block` runtime_switch_failed | 286 | 286 |
| other | `task.expire` timeout / lease_expired / agent_ended / stalled | 1046 | 899 (overlap) |
| other | `task.fail` provider_failure / channel_error / worker_fail | 499 | 441 (overlap) |
| other | other `task.block` env and runtime reasons | ~190 | ~180 (overlap) |

Attempts that reached a PR:

| population | attempts | no interruption | quota | session_lost | other | non-retried interruption |
|---|---:|---:|---:|---:|---:|---:|
| strict (complete on PR task) | 91 | 91 | 0 | 0 | 0 | 0 |
| broad (all attempts on PR tasks) | 202 | 93 | 2 | 0 | 107 | 2 |

Of the 107 broad-population attempts with an `other` event, 59 are decision waits
and 17 are `runtime_preparing`. Only 50 attempts carry any `other` event other than
a decision wait, and none of them is a `runtime_switch_failed` event.

Across all attempts, 79 interrupted attempts are non-retried (`other`), and 3 are
non-retried `quota` attempts.

## Limits

- `session_lost` is zero. The export has no `agent.lost` events and no reason containing
  `session_lost`. Lease expiries (239) and `agent_ended` (145) may be session losses that
  the export classifies as `other`, so the true session_lost count is not established.
- `runtime_switch_failed` shows a failed switch, not whether a replacement account was
  switched in mid-attempt and kept the session. The export cannot identify successful
  mid-attempt account switches, so the P4 account-switch path cannot be counted directly.
- `retried` is per attempt, not per interruption.
- The source is a preview DB snapshot from 2026-11-14 ~21:35 local; its last event is
  2026-11-15T00:15:51Z.

## Recommendation

**Keep the account-switch resume path unsupported for now.** Reasons, from these counts:

1. No attempt that reached a PR in the window was lost to a `session_lost` or to a
   quota interruption that was not retried. The strict PR population had no
   interruptions at all.
2. The 30-day affected count for the P4 gap (interrupted attempts on the unsupported
   path that were not retried) is 0 among PR-reaching attempts and at most 79 across
   all attempts. Most of those are `other` events of unknown kind, not session loss.
3. Same-node quota resume already covers the largest interruption class (397 attempts).
4. The export cannot measure the account-switch path, so building it now would be
   based on no measured demand.

Revisit when the export records mid-attempt account switches and their outcome
(session kept or lost). A `session_lost` count above zero, from the same export, would
also reopen the case.

## Follow-ups (not in this PR)

- Implement the account-switch resume path: not recommended now; see above.
- Add `agent.lost` and per-interruption `retried` to the export, and record switch
  success/failure, so the P4 path can be measured directly.
