# Checkpoint representation comparison (2026-11-21)

## Summary

This experiment compares two ways to save unpublished work from a task workspace:

- **Current checkpoint (`current`)**: the node-local, hash-verified checkpoint store implemented in `integrations/nanoclaw/argus-checkpoint.ts` (`work.bundle`, `staged.patch`, `unstaged.patch`, per-file untracked copies, and SHA-256 `manifest.json` under `ARGUS_CHECKPOINT_DIR`, specified in `docs/specs/task-checkpoint.spec.md`).
- **Hidden Git refs (`hidden_refs`)**: refs under `refs/argus/checkpoints/<task>/<n>` created inside the task repository via a temporary `GIT_INDEX_FILE` (`git add -A`, `git write-tree`, `git commit-tree -p HEAD`, `git update-ref`), with no external store, no manifest, and no file copies.

Both representations were exercised against disposable local Git fixtures using the real `argus-checkpoint.ts` module and the real Python `argus_api.fleet.workspace_archive` and `argus_api.fleet.workspace_restore` modules. Hidden Git refs preserve raw file content (including binary blobs) while `.git` remains intact and survive `workspace_archive` / `workspace_restore` via `git bundle create - --all`, but they do **not** preserve the current checkpoint format's recovery, isolation, confidentiality, size-limit, or verification guarantees.

## How to reproduce

Run the comparison script (prints 28 JSON lines, one per `(dimension, representation)` pair, and exits non-zero if any positive-control assertion fails):

```bash
node scripts/checkpoint-representation-compare.mjs
```

Run the `node:test` verification suite (12 tests covering all dimensions, workspace cleanup archive/restore via `PYTHONPATH=apps/api/src python3`, and `unsafeRevert` positive/negative controls):

```bash
node --test scripts/checkpoint-representation-compare.test.mjs
```

## Unsafe combinations

`unsafeRevert(state)` in `scripts/checkpoint-representation-compare.mjs` is a pure detector that checks whether reverting the workspace to `revertTarget` would discard changes the agent conversation already saw (`conversation: { sawChangesAt }`). It was verified on both representations in `unsafeRevert detects reverting below conversation state and allows safe reverts for both representations`:

- **Current checkpoint (`current`)**:
  - Negative test (unsafe): conversation saw `ckpt2.id`, revert target is older `ckpt1.id` in lineage `[ckpt1.id, ckpt2.id]` -> rejected with non-null reason (`unsafe_revert (current): revert target ... is older than changes seen at ...`).
  - Positive controls (safe): reverting to `ckpt2.id` when conversation saw `ckpt2.id`, or reverting to `ckpt2.id` when conversation saw `ckpt1.id` -> returned `null`.
- **Hidden Git refs (`hidden_refs`)**:
  - Negative test (unsafe): conversation saw `ref2.oid`, revert target is older `oid1` whose `git rev-list` ancestor set does not contain `ref2.oid` -> rejected with non-null reason (`unsafe_revert (hidden_refs): conversation saw changes at ..., not contained in revert target ...`).
  - Positive controls (safe): reverting to `ref2.oid` when conversation saw ancestor `oid1` or `ref2.oid` itself -> returned `null`.
  - Fail-closed sibling case: two sequential hidden refs (`sib1`, `sib2`) created from the same `HEAD` are siblings in Git history (`ancestorsOfSib2.has(sib1.oid) === false`), so Git commit ancestry alone cannot prove containment and `unsafeRevert` fails closed with a non-null reason unless external lineage is tracked.

## Recommendation

**Keep the current node-local hash-verified checkpoint format (`integrations/nanoclaw/argus-checkpoint.ts`).** Hidden Git refs do **not** preserve all current recovery guarantees.

Observed gaps in hidden Git refs:

1. **No manifest-level digest or identity binding**: there is no `checkpoint:<id>:<manifestSha256>` digest and no verification of `task_id`, `branch`, `repository_url`, or `node_id`; repointing a ref to another commit goes undetected.
2. **Confidentiality regression**: without a manifest/path filter, temporary-index `git add -A` captures `.env` and `*.pem` files into `.git/objects` and restores them, and produces no `skipped_sensitive` or `sensitive_in_commits` audit fields.
3. **No size-limit or retention enforcement**: `ARGUS_CHECKPOINT_MAX_BYTES` is not enforced, and refs/objects accumulate inside `.git` without bounded retention or proof-gated supersession.
4. **Lost with workspace `.git` outside the cleanup archive**: removing the workspace or losing the worker instance destroys `.git/refs/argus/*` and `.git/objects`. A fresh attempt cloning `origin` (or even plain `git clone <bundle>`) does not receive `refs/argus/*`; transfer requires an external bundle plus explicit `refs/argus/*:refs/argus/*` refspecs.
5. **Index flattening and sibling ancestry limits**: a single `commit-tree` flattens staged vs. unstaged index state, and hidden refs created from the same `HEAD` do not form a Git ancestor chain for safe-revert checks. Neither format preserves `.gitignore`'d files or non-Git directories.

The one area where hidden refs showed native integration is the `workspace_archive.py` / `workspace_restore.py` cleanup path (which uses `git bundle create - --all` and `refs/*:refs/*`), because hidden refs live inside `.git`. That narrow benefit does not offset the loss of manifest integrity, identity checks, secret exclusion, disk limits, and workspace-independent persistence provided by the current checkpoint format.
