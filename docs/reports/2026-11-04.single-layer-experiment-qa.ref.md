## Acceptance criteria

### 1. Opt-in path, default routing unchanged

`parseSingleLayerEnv` (`integrations/nanoclaw/argus-single-layer.ts:36`) returns
`{config: null}` for unset, empty, `0` and `off`, and refuses every engine other
than `claude` with `unsupported_engine`. `singleLayerFromEnv` is read once at
host start (`argus.ts:5279`). `singleLayerDecision` (`argus.ts:2994`) returns
`null` for a task absent from the assignment file, so the claim is untouched.
`renderTask` only takes the single-layer branch when `opts.singleLayer` is set
(`argus.ts:1287`); the test asserts the flag-off prompt is byte-identical to
`renderTask(base, new Map(), "claude")`.

The single-layer arm takes the implementation tier through
`harnessSelection(..., singleLayer=true)`, which calls `implementationScope` and
`selectModel` at the retry position the harness chain would take. With the flag
off, `harnessSelection` delegates to `selectHarnessModel` unchanged; the test
compares both across engines, complexities and failure counts.

**Observation, not a defect.** #200 also added a channel-side `pr_opened` relay
(`argus.ts:4353`) that runs in *every* execution mode, not only the
single-layer arm. #203 then rewrote the spec to say so
([progress milestones](../specs/progress-milestones.spec.md) 3.3,
[task deliverable](../specs/task-deliverable.spec.md) 3.4). Routing, leases,
prompt and model selection on the default path are unchanged, but the default
path's *reports* are not literally "byte-for-byte today's" as
[single-layer experiment](../specs/single-layer-experiment.spec.md) §2 still
says. The delegated arm can now emit `pr_opened` twice for one PR (the
delegate's tracker and the channel relay); §4.2 documents that the two emitters
can differ. A scoped follow-up should either narrow §2's wording or dedupe the
two emitters server-side. Neither is a blocker for this slice.

### 2. Isolated end-to-end test

`argus-single-layer.test.ts` runs the real adapter against a fake Argus API and
OneCLI gateway (no network, no model). It covers:

- **Claim:** the single-layer claim posts the implementation-tier harness
  selection with the arm marker and a prompt with no `argus-delegate`.
- **Lease-fenced progress:** a `409 stale_attempt` on `pr_opened` abandons the
  attempt; the following `COMPLETE` and `FAIL` post nothing.
- **Heartbeat / cancellation:** a heartbeat that rejects the lease stops the
  session and drops the rest of the reply.
- **Error:** `FAIL:` posts `/fail` under the attempt.
- **Structured delivery:** `pr_opened` is posted once with
  `{number, url}` before the reply is handled.
- **Default-off and control path:** flag off and an unlisted task produce an
  identical prompt, held accounts and harness selection; the `delegated` arm is
  the default path plus a marker; `executor_model_pinned`, `no_model_policy`
  and `engine_not_claude` fall back with the reason recorded.

### 3. Reproducible A/B protocol

`scripts/single_layer_ab.py` has three subcommands, each covered by
`scripts/test_single_layer_ab.py`:

- `assign` — deterministic stratified selection (largest remainder) and
  alternating arms within a stratum, keyed on `sha256(seed, experiment, id)`.
  The test asserts the same document from a reversed pool and a different one
  from a different seed.
- `export` — one record per claim, windowed to the next claim, read from a
  read-only database copy. Usage is `None` when any row is `not_reported` or
  null; the test builds a migrated database and checks the window boundaries.
- `analyze` — intention-to-treat per assigned arm. The fixture test asserts
  unknown usage is excluded and counted (`unknown: 1`), a fallback stays in its
  assigned arm (`attempts_off_arm: 1`), and time to PR and time to merge are
  reported separately with right-censored counts and `median_biased_low`.
  Without `--merged` there is no merge time at all (`n: 0`, `censored: 3`).

The export queries were checked against the real schema: `events`
(`subject_type='task'`, `kind='task.progress'`, `data.kind='pr_opened'`),
`model_selections` (`layer='harness'`, `explanation`), and `account_usage`
(`attempt`, `measurement`, `input_tokens`, `output_tokens`, `cost_usd`) all
exist with those columns in migrations `0029`, `0053` and the events index
`0058`.

### 4. Deterministic offline tests and a bounded operator procedure

No test reaches a provider. The runbook
([single-layer experiment](../runbooks/2026-11-04.single-layer-experiment.ref.md))
fixes a 20-task size, a dollar cap with a per-task `budget_usd`, a
"no decision" floor below 16 finished tasks, first-claim checks before the rest
run, five stop conditions (budget, a delegate call, a leaked secret, more than a
quarter of single-layer claims falling back, harm to the node) and rollback by
unsetting the flag and restarting. Nothing schedules, merges or deploys.

## Limitations

- **No real host run.** Verification boundary level 2 (a NanoClaw host with the
  flag on, checking the first claim of each arm) was not done: this image has no
  Docker daemon and no provisioned NanoClaw host. The spec already records it as
  not done.
- **No experiment.** Level 3 is the operator's, and this task forbids paid runs.
  No figure in this receipt is a result.
- **`pr_opened` depends on the model naming the URL.** A PR opened and never
  named is censored, which biases the single-layer arm's time to PR; the
  analysis cannot distinguish that from a missing PR (§4.2).
- **The two `pr_opened` emitters can disagree** on the same output, as noted
  under criterion 1.
