| Class | Behavior | Spec / code |

## Findings by severity

### P1 — none

Evidence against P1 classes in scope:

- **Data loss of unpublished git WIP (non-sensitive):** Archive-then-delete with verify (`archive()` → `verify()` → rename into place); failures rename the tombstone back (`_real`). Sensitive-only and non-git loss are **specified**, not accidental bypasses.
- **Safety bypass (delete live / wrong path):** Eligibility requires canonical UUID, `terminated`, nanoclaw pool/`instances_root` match, `shares_filesystem`; real runs take a DB lease with state re-read (`_lease`), tombstone rename, then fresh `_revalidate` + `_references` (agents/tasks, pool paths, Docker `mount_sources`, `/proc` mounts, process cwd/root). Roots use `check_root` (absolute, non-symlink, not system/docker/mount/overlap). Walk/delete use `O_DIRECTORY|O_NOFOLLOW`, `dir_fd` unlink/rmdir, `st_dev` checks.
- **Secret contents in audit/API:** `wa.sanitize()` for stored errors; events carry reason/bytes/`archived` bool, not file/git payloads; `test_internal_error_keeps_the_directory` asserts `SECRET` absent from the audit row JSON.

### P2

#### P2-1 — Unexpected-exception logging bypasses sanitization

**Where:** `workspace_cleanup.py` — `log.exception(...)` in `_run` (candidate loop ~462, run failure ~467), `_real` (~782), and `_log_failure` (~1133 with `exc_info=`).

**Issue:** Spec §3.5 / §5: logs/audit/API carry reason codes and exception **class names** only. Audit paths use `wa.sanitize(exc)`, but `log.exception` / `exc_info` emit the **full exception message** (and traceback).

**Evidence:** `test_internal_error_keeps_the_directory` raises `RuntimeError(SECRET)` from `scan` and only asserts the DB row is clean — that exception is not `ArchiveError`, so `_real`’s broad `except Exception` logs it via `log.exception` before storing `sanitize(exc)`.

**Impact:** Realistic when unexpected errors embed paths or payloads in `str(exc)`; controlled `ArchiveError`/`OSError` audit fields stay sanitized. Not a deliberate content logger, but a fail-open gap vs the sanitization rule.

#### P2-2 — Crash-resume after archive mis-reports `reason` / event `archived`

**Where:** `_resume` → `_delete(..., None, None)` (~851–858, ~894–895); `_finish` event payload `"archived": outcome.archive_path is not None` (~1126–1127).

**Issue:** After `_mark_deleting` stores `archive_path` and `reason=delete_interrupted`, a later run resumes and calls `_delete` with `archive_path=None`. On success, reason becomes **`no_wip`** even when WIP was archived. `_finish` does not clear the existing `archive_path` column (`is not None` guard), so the row can show `reason=no_wip` while `archive_path` still points at a bundle. The `workspace.cleaned` event can claim `archived: false`.

**Impact:** Correctness under the leftover-tombstone / multi-run path (the concurrency recovery path PR112 also touches). No second delete of the live tree, but audit/events become wrong for operators and automation.

### P3

#### P3-1 — Ownership pre-check runs after tombstone rename

**Where:** Spec §3.3 “before anything moves”; implementation: rename in `_real` (~768), then `measure` / `foreign_owner` in `_locked` (~808–814).

**Impact:** Foreign-owned trees are briefly renamed to `.argus-gc-<id>` then renamed back on `permission_denied`. Usually recoverable; diverges from the written order and widens the race window vs NanoClaw recreating `<id>`.

#### P3-2 — Mount-table check is at revalidation, not during `remove_tree`

**Where:** Spec §3.3 traversal: different `st_dev` **or** `/proc/self/mounts` entry stops deletion. `_remove` / `_measure` only enforce `st_dev` (~265–269, ~225–226). Mount paths are checked in `_references` before delete (~971–976).

**Impact:** Same-device bind mount (or a mount added after revalidation) is a TOCTOU hole vs a strict reading of §3.3. Mitigated by pre-delete mount scan and fail-closed unreadable mounts; residual under local privilege.

## Residual risks / limitations (not graded as defects)

1. **Non-git state is not archived** — deleted with the directory (spec §2; open question §4).
2. **Committed secrets remain in bundles**; `sensitive_in_commits` lists paths only; no rewrite (spec §3.5; runbook).
3. **Working-tree sensitive files** are omitted from artifacts then **deleted** with the tree; only path names survive in `skipped_sensitive`.
4. **Repo clean/smudge filters still run** during diffs (spec §3.8); hooks/fsmonitor disabled in `Git._argv`.
5. **Unprivileged process cwd/root** may be invisible (`process_refs` skips `OSError` per pid) — documented.
6. **Untracked under regenerable dirs** inside a worktree are not archived.
7. **PR112:** `_settle_tombstones` re-reads `lock_run_id` / `lock_expires_at` per tombstone (~678–707); covered by `test_a_tombstone_leased_after_the_scan_snapshot_is_left_alone`.
8. Defaults remain fail-safe: cleanup off, dry-run on (`config.py` / settings); real REST run needs admin + enabled + valid archive root (`routes.py` ~359–373).
