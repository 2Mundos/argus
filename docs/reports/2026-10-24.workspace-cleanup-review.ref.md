## Preservation stance (explicit — not total)

This feature **must not** be described as total preservation:

| Class | What happens | Never claim |
| --- | --- | --- |
| **Non-git NanoClaw state** (conversations, group memory, logs, caches outside git) | **Deleted with the instance directory; not archived** | That instance state was saved |
| **Committed secrets** (paths matching the sensitive allowlist that appear in local commits) | **Included in `git bundle create --all`**; listed under `sensitive_in_commits`; **no history rewrite** | That secrets were stripped from archives |
| **Untracked / staged / unstaged sensitive paths** | Omitted from archive artifacts (`skipped_sensitive` paths only), then **destroyed** with the tree | That working-tree secrets survive cleanup |

Bundles therefore can contain committed secret blobs. Operators must treat archive
roots as sensitive storage. Non-git loss and committed-secret inclusion are
**hard limits**, not bugs to waive.

## PermissionError test (diagnosed prior failure)

The old `chmod(0)` + `skipif(root)` test was insufficient: as root, DAC is
bypassed, deletion succeeds, and a `finally: chmod(0o700)` raises
`FileNotFoundError`. This PR adds:

1. Deterministic `PermissionError(EACCES)` fault injection on `measure`, with
   intact source / no leftover tombstone assertions.
2. A success-control twin that cleans without the fault.
3. Optional real mode-`0` DAC check when `euid != 0` (not a broad skip of the
   deterministic case).
