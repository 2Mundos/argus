## Acceptance criteria

### AC1 — lease and assignment checked before the forge request

`runRepositoryPreflight` (`integrations/nanoclaw/argus-repo-preflight.ts:351`)
orders the checks and returns before any probe:

1. **Lease** (`:395`) — `lease.held` (a `lease_id`), `lease.role === "repository"`
   and `lease.provider` matching the repository's provider; otherwise
   `assignment_missing` with "no task-scoped repository lease for this provider is
   held".
2. **Assignment** (`:402`, `:416`) — `verifyAssignment()` is an admin read of
   OneCLI's agent and secrets; a throw is `assignment_unverified`, and
   `assignmentConfirmed()` false is `assignment_missing` with a message naming
   which secret is unassigned or mis-scoped.
3. **Probe** (`:422`) — only after both pass.

`preflightReason` (`:290`) maps both assignment outcomes to
`env_repository_unavailable`, distinct from `env_repository_unreachable` for a
failed probe. **Verdict: implemented and exercised.**

**Concurrency and cleanup.** `assignmentConfirmed`/`verifyAssignment` are reads
only; nothing is written before the probe. `argus-onecli-preflight-lease.test.ts`
asserts a preflight lease leaves a live session's lease running (2 passed). The
`argus-gitea-lease.test.ts` suite (5 passed) covers lease cleanup. Twelve offline
tests drive every teardown path (`stop`, reap-by-key, gateway release, late
cleanup, listing) to a bounded failure, and the "one deadline" block fails closed
rather than leaking a container.

**What I could not verify.** The *concurrent-lease* case is asserted with a fake
driver and a fake gateway, not with two sessions against a real OneCLI. No
container test exercises a second worker holding the same task while a preflight
runs. See AC4.

### AC2 — bounded, redacted, attempt-correlated evidence

`PreflightEvidenceEvent` (`:298`) carries `preflight_id` (random 8 bytes),
`task_id`, `attempt`, `provider`, `access`, the `lease` triple
(`{source:"host", held, role, provider}`), the `assignment` block
(`{source:"onecli_admin_read", read, agent, secretMode, rest, git}`), the
`target` (`{source:"host", api_host, api_path, git_host, git_path}`) and the
`probe` (`{source:"preflight_session_verdict", helper_error, http_status,
permissions, push, visibility, authentication}`).

Every field is a closed value, a bounded integer, or a host and path the host
derived itself. `verdictEvidence` (`:148`) re-derives `authentication` from
`push`/`visibility` instead of trusting the container's claim. `safeText`
(`:94`) strips URL userinfo, `*_proxy` values, bearer/`ghp_`/`github_pat_`/`sk-`
tokens and `token|secret|password|api_key|authorization` assignments, collapses
non-printables and truncates.

The test "no secret, auth header, proxy userinfo or sensitive URL reaches the
event or the error" pushes a leaky string through the task id, the assignment
result and both probe error types, then asserts the token, the proxy userinfo
and `x-access-token:` are absent from the error and from `JSON.stringify(event)`,
and bounds both (`error ≤ 340`, event `< 2000`). The docker suite has an
equivalent redaction case with a real container (currently skipped; see AC4).

**Verdict: implemented and exercised offline.** The `attempt` correlation is
asserted in "passes with the assignment confirmed and the probe's evidence,
attempt-correlated".

### AC3 — distinguishable outcomes, `unknown` preserved

`failedOutcome` (`:174`) maps, and 15 parameterized cases in
"outcome classification" assert each:

| Input | Outcome |
| --- | --- |
| `unauthorized` / `forbidden` / `not_found` (401/403/404) | `forge_denied` |
| `policy_denied` with private repo (credential proven) | `forge_denied` |
| `policy_denied`, public repo without push | `unknown` |
| `policy_denied`, permissions object absent | `unknown` |
| `policy_denied`, unlabelled repo without push | `unknown` |
| a verdict that *claims* `authentication:"proven"` without `push` | `unknown` |
| `network_error` | `network_failure` |
| `rate_limited` (429) / `server_error` (502) | `unknown` |
| no verdict (exit 137) | `session_failure` |
| `ok` verdict for write without `push` | `unknown` |

Two properties the incident asked for hold in code and in test: a public-repository
answer is never named anonymous (the word does not appear in the module; the
docker test asserts `expect(JSON.stringify(events)).not.toMatch(/anonymous/i)`),
and `permissions.push` is described in the helper's own comment as the forge's
effective write bit for *that request*, explicitly "not proof of OAuth scope or
fine-grained token rights" (`gitea-api.mjs:1390`). `unknown` is a first-class
outcome, not a fallback to success.

**Verdict: implemented and exercised offline.**

### AC5 — audited existing-PR reconciliation

`bind` (`apps/api/src/argus_api/tasks/pr_binding.py:44`) and
`reconcile_delivery` (`:153`) implement 3.7 and 3.8. Fencing is exact:

- **Repository** (`_repository`, `:109`) — the caller's `repository` must equal
  the project's proven repository (`pr_wrong_repository`, 422), and it is checked
  *before* the forge read, so a credential is never sent to an input-named host.
  The test asserts `reads == []` for that case.
- **PR and head** (`_bound`, `:130`) — a PR already bound at a different head is
  `pr_already_bound`; `reconcile_delivery` refuses a forge head that differs from
  the named head (`pr_stale_head`, 409).
- **Merge** — `pr_not_merged` (409) and a missing merge commit is `pr_unverified`
  (409).
- **Stale failure** (`_eligible`, `:223`) — the named failure must be the task's
  current failure and must be `deliverable_missing`; otherwise `stale_failure` or
  `failure_not_deliverable_missing`. A task not in `failed` is `task_not_failed`.
- **One PR** — a second PR on the task is `pr_ambiguous`.
- **Replay** (`_reconciled`, `:311`) — a replay with the same PR and head returns
  the task unchanged; a different PR or head is `delivery_already_reconciled`.
- **Terminal states** — `test_reconciling_leaves_other_states_alone` covers
  `succeeded`, `cancelled`, `ready`; `test_binding_never_resurrects_a_terminal_task`
  covers binding.
- **No gate waiver** — `reconcile_delivery` ends in `service.review_failed`, so
  the task lands in `in_review` and still needs an accept;
  `test_reconciling_a_merged_delivery_opens_review_and_keeps_every_gate` asserts
  it. The exact-head forge check is untouched.
- **Audit** — `task.pr_reconciled` / `task.delivery_reconciled` events record the
  actor, reason, repository, PR, head, failure id and revision.
- **Concurrency** — every check re-runs inside the write;
  `test_concurrent_reconciliations_make_one_transition` asserts a single
  transition. The forge read is outside the write
  (`test_a_forge_read_while_another_request_writes_is_not_inside_a_write`).

The incident case is a named test:
`test_incident_1a7c140b_binding_alone_leaves_no_way_to_review`.

Entry points exist at all three layers — `POST /api/tasks/{id}/reconcile-pr` and
`.../reconcile-delivery` (`tasks/routes.py:705`, `:719`) and the MCP tools
`reconcile_task_pr` / `reconcile_task_delivery` (`mcp_server.py:767`, `:797`) —
all calling the same service code.

**Verdict: implemented and exercised.** 11 of the deliverable suite's tests are
the reconciliation path; the whole file is 70 passed.

## Limitations

- **AC4 is not established.** No Docker daemon here; the real-image suite is 14
  skipped. The host-side 13-passed run is operator-reported, synthetic, and
  image-version-sensitive.
- **No real OneCLI scoping proof** anywhere in this attempt. Every injected path
  is synthetic unless noted in the probe above, and that probe is a helper run,
  not a session.
- **The preflight tests run in no gate.** `provision.sh check` lists 30 files and
  omits both preflight suites; CI's green `nanoclaw-vitest` therefore says nothing
  about them. Adding them to that list is a one-line change with no behaviour
  risk, but it needs a code change and no executor is leased to this worker.
- **The `docker-integration` CI job** runs `make test-docker`, which is the
  control-plane image test and does not include `argus-repo-preflight.docker.test.ts`
  (it needs `ARGUS_PREFLIGHT_DOCKER_IMAGE`), so even the manual CI path does not
  reach it.
- **Container test hygiene.** The suite's deadline case kills the first container
  carrying a *global* label (`argus-preflight=1`), which is why the earlier host
  run excluded it. On a busy host it can kill another run's container.
- **52 unrelated tests fail in this container** for harness reasons (see above);
  they are not attributed to this change and are not counted as passes.
